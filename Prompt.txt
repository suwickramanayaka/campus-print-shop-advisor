## Phase 2: Build the agreed system

### Mandatory Prolog concepts
Each one must be used meaningfully, and the code must have a short comment tag such as `% CONCEPT: findall/3`:
- Facts and rules (knowledge base)
- **List manipulation**: head/tail recursion, `append/3`, `sum_list/2`, `sort/2` or `msort/2`, `nth1/3`, plus at least one custom recursive list predicate
- **Membership**: `member/2`, and also a custom `member`-style predicate to show understanding
- **Length**: `length/2`
- **Set aggregation**: `findall/3`, `bagof/3` **and** `setof/3`, with at least one case showing how they differ (e.g. `setof` gives sorted, unique results; `bagof` fails on no solutions where `findall` returns `[]`)
- **Database manipulation**: `:- dynamic`, `assert/asserta/assertz`, `retract/1`, `retractall/1`
- **Cut (`!`)**: a green cut for efficiency and a red cut that changes logic
- **Fail**: the `fail`-driven loop for printing all records, and `\+` (negation as failure)
- **Input/Output**: `read/1`, `write/1`, `nl/0`, `format/2` for aligned tables
- Recursion, arithmetic (`is`, comparisons) and `between/3` for input validation
- Interactive questioning: ask the user for information, store the answers as dynamic facts so no question is asked twice, and clear them on a new session
- Invalid-input handling (bad menu choices, unknown names, non-numeric values) without crashing

### User interface
1. **Primary: console menu.** Entry point `start.` shows a clear, boxed main menu with submenus. It loops until Exit, with clean formatting, headers and aligned tables.
   - `read/1` needs a trailing full stop, which is confusing in a demo. Use `read_term/3` with a clear hint, **or** `read_line_to_string/2` with parsing. Choose and justify.
2. **Secondary: simple web UI** using SWI-Prolog's built-in HTTP libraries (`thread_httpd`, `http_dispatch`, `html_write`):
   - Started with `start_web.`, served at `http://localhost:8080`.
   - Calls the **same** core predicates as the console version, with no duplicated logic.
   - Do **not** use XPCE (it needs XQuartz on macOS and is fragile).
